# 팀 밈 목록

한 댓글에는 아래 문구 중 상황에 정확히 맞는 하나만 사용한다.

| 상황 | 문구 |
| --- | --- |
| 실패 경로나 회귀 테스트를 빼서 재작업할 수 있음 | `대충 하면~? 꼭 두 번 일한다~` |
| 작은 문제를 지금 막지 않으면 수정 범위가 커짐 | `호미로 막을 걸~? 가래로 막는다~` |
| 작은 비용이나 지연이 매번 누적됨 | `가랑비에~? 옷 젖는다~` |
| 병합 전에 한 번 더 검증해야 함 | `돌다리도~? 두들겨 보고 건너라~` |
| 불필요한 API 또는 모델 호출을 줄임 | `땅을 파봐라, 토큰 하나라도 나오나.` |
| 무료처럼 보여도 시간이나 운영 비용이 듦 | `세상에 공짜가 어디 있어... 그냥~` |
| 작은 변경에 구조가 지나치게 커짐 | `배보다~? 배꼽이 더 크다~` |
| 모델과 도구를 역할에 맞춰 나눔 | `모델도 적재적소에 써야 합니다.` |
| 과거 PR과 회의록을 현재 판단에 사용함 | `이런 게 온고지신입니다.` |
| 회귀를 테스트와 정책 보완으로 남김 | `여기까지 하면 전화위복입니다.` |

아래 표현은 검증을 완료한 가벼운 팀 대화에만 사용한다. 정책 위반을 지적하는 리뷰에는
상대를 평가하는 말로 읽힐 수 있으므로 기본적으로 사용하지 않는다.

- `고마워우이~`
- `성공시대 시작됐다~`
- `이거 신통방통합니다.`
- `듣는 둥~ 마는 둥~`
- `어른 말을 그냥... 응? 잘 들어야 돼~`
- `어른 말을 개코로 알아?! 응? 그냥...`
- `잔소리도 다~ 응? 애정이 있어서 하는 거야~`
- `다 뼈가 되고 살이 된다~?`
- `다 내 자식 같아서 하는 말이야~`

`듣는 둥~ 마는 둥~`부터 `어른 말을 개코로 알아?! 응? 그냥...`까지는 본인이 이미
공유된 내용을 놓친 일을 스스로 말할 때만 사용한다. 특정
동료의 태도를 지적하거나 리뷰 의견을 무시했다고 몰아붙이는 문장에는 사용하지 않는다.

마지막 세 문구는 친한 팀의 가벼운 대화에서만 사용한다. 실제 정책 위반, 실수나 태도를
지적하는 리뷰, 원하지 않은 조언을 정당화하는 문장에는 사용하지 않는다.

정책 검수를 실제로 끝낸 뒤 후보가 하나도 없으면 아래 순서로 쓸 수 있다. 검수를 실행하지
못했거나 후보에 반대 근거가 남아 있으면 문제가 없다고 단정하지 않는다.

```text
음~~~ 어디~ 보자~?

문제가...없네..?

# 해가 서쪽에서 뜨겄어~?
```

문구를 빼도 설명이 완전해야 한다. 실제 상황과 맞지 않으면 밈 없이 제출한다.
