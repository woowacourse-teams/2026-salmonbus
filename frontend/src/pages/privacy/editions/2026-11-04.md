# 개인정보 처리방침

연어버스 팀(이하 "팀")은 경기도 광역버스의 좌석 예보를 보여 주는 서비스 연어버스를 운영합니다. 팀은 「개인정보 보호법」 제30조에 따라 연어버스 이용자의 개인정보를 어떻게 처리하는지 알리려고 이 처리방침을 공개합니다.

이 처리방침은 연어버스 웹사이트(https://www.salmonbus.com)와 연어버스 iOS 앱에 적용됩니다. iOS 앱은 앱 안에서 연어버스 웹사이트를 띄웁니다. 그래서 앱에서도 웹사이트와 같은 개인정보를 처리합니다. 앱에서만 처리하는 정보는 그 정보를 다루는 절에 따로 적었습니다.

시행일: 2026년 11월 4일

이 처리방침에서 쓰는 말은 아래와 같습니다.

- 회원: 카카오 로그인 또는 Apple로 로그인으로 연어버스에 가입한 사람입니다.
- 이용자: 회원과, 로그인하지 않고 연어버스를 쓰는 사람을 함께 부르는 말입니다.
- 이용 기록: 이용자의 브라우저가 Amplitude로 보내는 화면 조회, 클릭, 서비스 이벤트 기록입니다.
- 화면 기록: 이용자의 브라우저가 Amplitude Session Replay로 보내는 화면 구조와 화면 변화 기록입니다.
- 오류 정보: 이용자의 브라우저가 Sentry로 보내는 오류 내용입니다.

## 1. 개인정보의 처리 목적

팀은 아래 목적으로만 개인정보를 처리합니다. 목적이 바뀌면 14절에 따라 이 처리방침을 바꾸고 미리 알립니다.

| 목적 | 하는 일 |
| --- | --- |
| 회원 가입과 관리 | 카카오나 Apple 계정으로 회원을 확인합니다. 로그인 상태를 유지합니다. 회원이 탈퇴하면 회원 정보를 지우고 카카오나 Apple과의 연결을 끊습니다. |
| 즐겨찾기 저장 | 회원이 고른 노선, 정류장, 방향을 즐겨찾기 그룹에 저장하고 다시 보여 줍니다. |
| 서비스 이용 분석 | 이용자가 어떤 화면과 기능을 쓰는지 이용 기록과 화면 기록으로 살펴보고 서비스를 고칩니다. |
| 서비스 안내와 이용자 의견 수집 | 화면에 안내 말풍선을 띄웁니다. 설문을 띄워 응답을 받습니다. |
| A/B 테스트 | A/B 테스트를 하는 기간에 한해, 이용자를 실험 안 가운데 하나에 배정하고 안마다 이용 결과를 비교합니다. |
| 오류 수집 | 화면 오류와 서버 응답 실패 정보를 모아 원인을 찾고 고칩니다. |

카카오와 Apple에서 받는 정보는 회원 가입, 로그인, 탈퇴할 때 연결 끊기에만 씁니다.

## 2. 처리하는 개인정보의 항목

### 2-1. 동의 없이 처리하는 항목과 법적 근거

팀은 정보주체의 동의를 받아 처리하는 개인정보가 없습니다. 이 절에 적은 개인정보는 모두 동의 없이 처리합니다. 팀은 「개인정보 보호법」 제22조 제3항에 따라 항목 묶음마다 처리의 법적 근거를 밝힙니다.

| 항목 묶음 | 자세한 항목 | 대상 | 법적 근거 |
| --- | --- | --- | --- |
| 카카오와 Apple에서 받는 정보 | 2-2 | 회원 | 「개인정보 보호법」 제15조 제1항 제4호 (서비스 이용 계약의 이행) |
| 서비스가 만들거나 회원이 입력하는 정보 | 2-3 | 회원, 로그인하거나 탈퇴를 진행하는 사람 | 제15조 제1항 제4호 (서비스 이용 계약의 이행) |
| Amplitude로 보내는 정보 (이용 기록, 화면 기록, 안내와 설문 기록, A/B 테스트 배정) | 2-4 | 모든 이용자 | 제15조 제1항 제4호 (서비스 이용 계약의 이행) |
| 설문 응답 | 2-5 | 설문에 답한 이용자 | 제15조 제1항 제4호 (서비스 이용 계약의 이행) |
| Sentry로 보내는 오류 정보 | 2-4 | 모든 이용자 | 제15조 제1항 제4호 (서비스 이용 계약의 이행) |

팀은 서비스를 제공하고 오류를 고치는 데 이 정보가 필요해서 처리합니다. Amplitude로 보내는 정보는 스위치로 멈출 수 있습니다(8절, 10절).

### 2-2. 카카오와 Apple에서 받는 정보

- 연어버스 회원 가입과 로그인은 카카오 로그인 또는 Apple로 로그인으로만 합니다.
- 팀은 카카오와 Apple에 openid 범위 하나만 요청합니다. 이름, 이메일, 전화번호, 프로필 사진은 요청하지 않습니다.
- 팀은 로그인할 때 받는 ID 토큰에서 소셜 계정 식별자만 저장합니다. 소셜 계정 식별자는 로그인 제공자 이름과 그 제공자의 회원 식별자(카카오 회원번호 또는 Apple 사용자 식별자)입니다.
- ID 토큰의 다른 값은 회원을 찾는 데만 쓰고 저장하지 않습니다.
- 카카오와 Apple이 주는 액세스 토큰은 요청 하나를 처리하는 동안만 쓰고 저장하지 않습니다.
- iOS 앱에서는 카카오톡 앱이나 Apple 로그인 창이 ID 토큰을 앱에 주고, 앱은 그 토큰을 앱 안 웹 화면에 넘겨 웹과 같은 방법으로 로그인합니다. 앱은 ID 토큰을 저장하지 않습니다.

### 2-3. 서비스가 만들거나 회원이 입력하는 정보

팀은 아래 정보를 연어버스 서버의 데이터베이스(AWS 서울 리전)에 저장합니다.

| 항목 | 대상 | 만드는 방법 | 쓰는 곳 |
| --- | --- | --- | --- |
| 소셜 계정 식별자 (로그인 제공자 이름, 카카오 회원번호 또는 Apple 사용자 식별자) | 회원 | 로그인할 때 제공자의 ID 토큰에서 받습니다. | 회원 확인, 로그인 |
| 회원 내부 번호 | 회원 | 가입할 때 데이터베이스가 차례로 매깁니다. 서버 밖으로 보내지 않습니다. | 회원 정보 연결 |
| 회원 공개 ID (무작위 UUID) | 회원 | 가입할 때 서버가 무작위로 만듭니다. | 로그인 쿠키 안의 회원 확인 값, Amplitude 이용 기록 연결 |
| 닉네임 (2자에서 10자, 한글, 영문, 숫자) | 회원 | 가입할 때 서버가 무작위로 만듭니다. 회원이 직접 바꿀 수 있습니다. 카카오 프로필 닉네임은 받지 않습니다. | 마이페이지 표시 |
| 가입 시각, 마지막 로그인 시각 | 회원 | 서버 시계로 남깁니다. 마지막 로그인 시각은 카카오나 Apple로 로그인할 때마다 바꿉니다. | 회원 관리 |
| 즐겨찾기 그룹 (그룹 이름 10자까지, 순서, 3개까지) | 회원 | 회원이 입력합니다. | 즐겨찾기 저장 |
| 즐겨찾기 (노선 ID, 정류장 ID, 방향, 순서) | 회원 | 회원이 고릅니다. | 즐겨찾기 저장 |
| 로그인 유지 기록 (로그인 묶음 번호, 갱신 차수, 시작 시각, 갱신 시각, 만료 시각) | 회원 | 로그인하거나 토큰을 갱신할 때 서버가 만듭니다. 토큰 값, IP 주소, 기기 이름은 저장하지 않습니다. | 로그인 상태 유지 |
| 로그인 중 임시 정보 (로그인 요청 확인 값 state와 nonce, 로그인 뒤 돌아갈 화면 주소, Apple 탈퇴를 진행하는 회원의 회원 공개 ID) | 로그인하거나 Apple 탈퇴를 진행하는 사람 | 로그인이나 Apple 탈퇴를 시작할 때 서버가 만듭니다. | 로그인, Apple 탈퇴 |
| 카카오 연결 해제 대기 기록 (로그인 제공자 이름, 카카오 회원번호, 시도 횟수, 마지막 오류 문구 200자까지) | 탈퇴한 카카오 회원 | 카카오 회원이 탈퇴할 때 서버가 만듭니다. | 탈퇴한 회원의 카카오 연결 끊기 |
| Amplitude 삭제 요청 대기 기록 (회원 공개 ID, 시도 횟수) | 탈퇴한 회원 | 회원이 탈퇴할 때 서버가 만듭니다. | 탈퇴한 회원의 Amplitude 기록 삭제 요청 |

연어버스 서버가 요청을 받을 때는 이용자 기기의 IP 주소와 User-Agent(브라우저와 OS를 알려 주는 문자열)가 함께 옵니다. 서버는 이 둘을 데이터베이스와 서버 로그에 저장하지 않습니다.

서버 로그에는 요청마다 새로 만드는 요청 번호, 요청한 API 경로, 실패한 요청의 상태 코드와 오류 코드, 오류 종류, 노선 ID를 남깁니다. 로그인과 탈퇴 결과는 로그인 제공자, 결과, 오류 종류만 남깁니다. 서버 로그에는 회원 공개 ID, 회원 내부 번호, 닉네임, 소셜 계정 식별자를 남기지 않습니다.

연어버스 웹사이트의 전송 서비스(Amazon CloudFront)는 접속 기록을 남기지 않습니다.

### 2-4. 이용 중 자동으로 수집하는 정보

이용자가 연어버스를 쓰는 동안 이용자의 브라우저가 아래 정보를 Amplitude와 Sentry로 직접 보냅니다. iOS 앱에서는 앱 안의 웹 화면이 보냅니다. 두 회사는 미국 회사입니다. 국외 이전 내용은 8절에 적었습니다.

#### Amplitude로 보내는 정보

이용자가 "서비스 개선에 참여하기" 스위치를 끄면 그 기기에서는 아래 정보를 보내지 않습니다(8절, 10절). 이 스위치는 처음에 켜져 있습니다. 끄면 그때까지 쌓인 기록(스위치를 끈 기록 포함)을 한 번 보낸 뒤 더는 보내지 않습니다. iOS 앱과 브라우저는 설정을 따로 저장하므로 쓰는 곳마다 꺼 주세요.

- **기기와 브라우저 정보.** 기기 ID(브라우저마다 무작위로 만드는 번호), 세션 ID, User-Agent, 브라우저 언어, 플랫폼, Amplitude가 User-Agent로 추정하는 브라우저, OS, 기기 모델을 보냅니다. 실행 환경(웹 또는 iOS 앱)과 iOS 앱 버전도 보냅니다. iOS 앱 버전은 앱이 웹 화면에 알려 줍니다.
- **회원 공개 ID.** 회원이 로그인하면 이용 기록에 회원 공개 ID를 붙입니다. 로그아웃하면 회원 공개 ID를 떼고, 기기 ID는 그대로 둡니다.
- **자동 이용 기록.** Amplitude SDK의 자동 수집 기능이 아래 기록을 보냅니다.
  - 본 화면의 주소(쿼리 포함)와 제목, 이전 화면의 주소
  - 세션 시작과 끝
  - 처음 들어온 경로: 이전 사이트 주소, UTM 값, 광고 클릭 ID
  - 누른 요소의 글자(255자까지), aria-label, 태그와 CSS 경로, 화면 안 위치, 화면 크기
  - 입력칸을 바꾼 사실(입력한 값은 보내지 않습니다), 폼 시작과 제출
  - 파일 다운로드
  - 화면에 보인 요소 목록과 가장 많이 내린 스크롤 위치
  - 화면 성능 수치(Web Vitals)
  - 연달아 누른 클릭과 반응이 없는 클릭
  - 서버가 오류로 답한 요청의 주소, 요청 방식, 응답 상태 코드
- **서비스 이벤트.** 연어버스 웹 코드가 아래 행동을 이벤트로 보냅니다.
  - 행동: 노선 선택, 노선 검색 결과 없음, 노선 화면(노선을 고르면 나오는 지도와 정류장 목록) 조회, 노선 화면을 볼 수 없음, 방향 전환, 정류장 펼침, 즐겨찾기 버튼 누름, 즐겨찾기 담기, 로그인 시작, 로그인 결과, 새 소식 창 조회, 새 소식 창 닫기
  - 노선과 정류장 정보: 노선 ID, 노선 상태, 새 노선 여부, 정류장 ID, 정류장 순서, 방향
  - 검색 정보: 결과가 없는 검색어(숫자만), 검색 결과 순서와 개수, 노선을 고를 때 입력한 글자 수(검색어 자체는 보내지 않습니다)
  - 예보 화면 정보: 예보 모델 버전, 예보를 만든 뒤 지난 시간, 운행 중인 차량 수, 예보 판정과 판정별 정류장 수, 남은 정류장 수, 도착 차량 수, 화면을 띄우는 데 걸린 시간, 노선 화면을 볼 수 없는 이유와 오류 종류
  - 화면 이용 정보: 화면에 들어온 경로, 펼친 정류장의 화면 안 위치와 펼친 순서

## 9. 개인정보의 안전성 확보조치

팀은 개인정보를 안전하게 처리하려고 아래 조치를 합니다.

### 9-1. 기술적 조치

- 웹사이트, 연어버스 서버, Amplitude, Sentry 사이의 통신은 HTTPS로 암호화합니다.
- 로그인 쿠키에는 HttpOnly와 Secure 속성을 붙입니다. 그래서 웹 페이지 스크립트는 로그인 쿠키를 읽지 못하고, 브라우저는 로그인 쿠키를 HTTPS 연결로만 보냅니다.
- 서버는 리프레시 토큰 값을 데이터베이스에 저장하지 않습니다. 서버는 토큰을 받을 때마다 서명으로 다시 계산해 확인합니다.
- 서버는 CSRF 토큰 쿠키로 다른 사이트가 이용자 몰래 요청을 보내지 못하게 합니다.
- 서버는 카카오와 Apple의 액세스 토큰을 저장하지 않습니다.
- 서버 로그에는 IP 주소, User-Agent, 회원 공개 ID, 회원 내부 번호, 닉네임, 소셜 계정 식별자를 남기지 않습니다.
- 팀은 카카오와 Apple에 openid 범위만 요청해 받는 정보를 줄입니다.
- 화면 기록은 입력칸 값, 닉네임, 즐겨찾기 그룹 이름을 가립니다.
- Sentry 오류 정보에서는 연어버스 밖 주소의 쿼리와 응답 본문 안의 토큰, 쿠키, 비밀번호 값을 지웁니다.

### 9-2. 관리적 조치

- 서버와 데이터베이스에 접근할 수 있는 사람은 운영을 맡은 팀원 4명입니다.
- 팀원이 팀을 떠나면 공용 서버 접속 키와 데이터베이스 비밀번호를 새로 바꾸고, Amplitude, Sentry, Grafana Cloud에서 그 팀원의 계정을 뺍니다. AWS 계정 권한은 운영진에게 회수를 요청합니다.
- 서버 로그인 기록을 31일 동안 남깁니다.
- 데이터베이스 비밀번호와 로그인 서명 키는 서버 안 관리자만 읽을 수 있는 파일에 두고, 저장소에 올리지 않습니다.
- 서비스 프로그램은 로그인할 수 없는 전용 사용자로 돌고, 관리용 포트는 서버 밖에서 접속할 수 없습니다.

## 10. 자동 수집 장치의 설치, 운영과 거부

### 10-1. 쿠키와 브라우저 저장소

- 쿠키는 웹사이트가 이용자의 브라우저에 저장하는 작은 데이터입니다. 브라우저는 그 웹사이트에 요청할 때 쿠키를 함께 보냅니다.
- 브라우저 저장소(localStorage, sessionStorage)는 웹 페이지가 브라우저 안에 데이터를 저장하는 곳입니다.
- sessionStorage에 저장한 데이터는 탭을 닫으면 지워집니다.
- localStorage에 저장한 데이터는 이용자가 지울 때까지 남습니다.
- 앱 저장소는 iOS 앱이 기기 안 자기 공간에 데이터를 저장하는 곳입니다. 앱을 지우면 함께 지워집니다.

- 브라우저의 사이트 데이터를 지우면 `salmonbus.analyticsOptOut`도 지워져 "서비스 개선에 참여하기" 스위치가 다시 켜집니다. 그 기기에서 다시 끄려면 스위치를 한 번 더 꺼야 합니다.
