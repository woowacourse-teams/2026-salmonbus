# 02. 컨벤션 현황

기준 `dev` 6f70826. 수치는 정규식 집계이고, 실례는 파일을 읽고 골랐다. 경로에서 `src/main/java/com/gustler/backend/` 는 `…/` 로 줄였다. 서식·명명을 강제하는 설정 파일(`.editorconfig`, checkstyle, spotless)은 없다. 지금 규칙은 리뷰와 ArchUnit 규칙 2개로만 지켜진다.

## 1. 서식

| 관례 | 실측 | 실례 |
| --- | --- | --- |
| 매개변수는 한 줄에 하나, 닫는 괄호는 다음 줄. 매개변수가 하나여도 같다 | 단일 매개변수 메서드 388개가 이 서식, 26개는 한 줄 | `…/api/board/application/BoardCachePolicy.java` `maxAgeAt(`↵`OffsetDateTime observedAt`↵`)` |
| 원시형 매개변수와 지역변수에 `final` | worker 150 / api 8 / migration 0. 객체형 매개변수 `final` 은 worker 6 | `…/collector/ObservationCollector.java` `collectOn(final long routeVersionId, String upstreamRouteId, …)` |
| import 한 블록, ASCII 순, static 먼저, 와일드카드 없음 | 예외 3 파일: import 블록 안에 빈 줄 | `…/processor/ForecastJob.java`, `ForecastBatchWriter.java`, `…/seatdistribution/BundleLoader.java` |

### 2-3. 상수

- 이름은 UPPER_SNAKE. 예외는 로거 `log` 11곳뿐이다.
- 매직 넘버에 이름을 붙인다. `ONE_ROW_CHANGED`(`JdbcCallQuotaRepository`), `FIRST_ATTEMPT`, `NO_GENERATION_YET`, `MAX_APPROACHING_VEHICLES`. 테스트도 같다(`ALREADY_USED_UP`, `ONE_SEAT_LEFT`, `TWO_CALLS`).
- SQL 상수는 `동사_대상` 이고 `_SQL`·`_QUERY` 접미가 없다. worker jdbc 37개 중 `SELECT_*` 18, 나머지는 `UPSERT_FORECAST`, `MARK_FORECAST_COMPLETED`, `SETTLE_FORECAST`, `RESERVE`, `REGISTER`, `LOCK_DEPLOYMENTS`, `RETIRE_ACTIVE_DEPLOYMENT` 처럼 하려는 일을 적는다. 갱신문도 `UPDATE_` 가 아니라 뜻으로 이름 짓는다.
- 버전 문자열은 `CURRENT_*_VERSION` 공개 상수로 둔다(`CollectedObservations.CURRENT_NORMALIZATION_VERSION`, `StopDemandStatisticsJob.CURRENT_CALCULATION_VERSION`). migration-tool 이 후자를 가져다 쓴다.
- 서울 시간대는 `KOREA`(`CallQuotaLedger`, `SeoulDay`)로 이름 붙인 곳과 그 자리에서 `ZoneId.of(...)` 하는 곳(migration 9 파일)이 섞여 있다.

### 2-4. 패키지·JPA 논리명

- 패키지는 소문자 한 단어. 두 단어는 붙여 쓴다(`seatdistribution`).
- `@Entity(name=…)` 는 worker 4개 전부, api board 4개만 지정하고 api vehicle 3개·route 3개는 기본 이름이다. api-app 안에서 `ObservationBatchJpaEntity` 가 두 패키지에 있어 board 쪽만 이름을 붙여 충돌을 피했다.
- DDL 제약·인덱스 이름(`ck_`, `ux_`, `fk_`, `ix_`, `pk_`) 은 컨플루언스 「0817 BE DB 스키마」의 표기 규약을 따르고, SQL 상수와 주석이 이 이름을 그대로 부른다(`ON CONFLICT ON CONSTRAINT pk_daily_call_quota`, javadoc 의 `ck_forecast_expected_seats`).

## 3. 예외 처리

세 모듈이 세 방식이다.

| | api-app | worker-app | migration-tool |
| --- | --- | --- | --- |
| 기반 | `ApiException(ErrorCode, retryAfter)` 추상 클래스 + 하위 5개 | 표준 예외 + 커스텀 2개 | `MigrationException(code)` 1개 |
| 불변식 위반 | `Objects.requireNonNull(x, "…null일 수 없습니다.")` | `IllegalArgumentException("아는 잔여석은 음수일 수 없다: " + seats)` 72곳 | `MigrationException("SOURCE_ACCEPTANCE_POLICY_INVALID")` |
| 설정 오류 | – | `IllegalStateException("gbis.base-url must not be blank")` (영어 3곳) | `MigrationException("CONFIG_REQUIRED_…")` |
| 상류·DB 오류 | 어댑터가 `DataAccessException` → `ServiceUnavailableException`. 서비스도 데이터 불일치를 `ServiceUnavailableException` 으로 낸다 | 상류 오류는 예외가 아니라 값. sealed `GbisLocationResult` 10가지, `GbisRouteResult`, `GbisRawResponse` | `SQLException`·`IOException` 을 `MigrationException` 으로 감싼다. `throws` 140곳 |
| 잡는 곳 | `ApiExceptionHandler`(3 핸들러 + `handleExceptionInternal`), `ApiErrorController`, `ContainerErrorResponseValve` | `ObservationCollector.readOrGiveUp` 이 `RuntimeException` 을 `NoResponse` 로 접음 | `MigrationCli.main` 이 코드만 JSON 으로 출력 |
| 메시지 언어 | 한국어(`ErrorCode` 메시지) | 한국어 58, 영어 3 | 영어 코드 393 |

실례.

- 어댑터의 잡는 범위가 다르다. `…/api/board/persistence/jpa/JpaBoardQueryRepository.java` 는 `DataAccessException` 을, `…/api/route/persistence/jpa/JpaRouteQueryRepository.java` 는 `DataAccessResourceFailureException` 만 잡는다.
- `…/collector/ForecastAlreadyCompletedException.java` 는 `IllegalStateException` 을 안 쓴 이유를 javadoc 으로 적었다. 리포지터리 빈에서 나가면 스프링이 `InvalidDataAccessApiUsageException` 으로 바꿔 규칙 위반과 영속성 오류가 안 갈린다는 것이다.
- `…/collector/GbisProperties.java` 는 원인 예외를 일부러 안 달고 새로 던진다. `UriUtils` 메시지에 인증키 뒷부분이 실리기 때문이다.
- worker 는 `catch (Exception` 2곳, migration 10곳이고 `Throwable` 은 없다.

## 4. DTO 와 record

- 값·DTO·읽기 모델·설정은 record 다. 형 선언 474개 중 record 238개. compact 생성자에서 검증하고 `List.copyOf`·`Map.copyOf` 로 방어 복사한다(`…/api/board/domain/Board.java`, `…/collector/CollectedObservations.java`).
- 변환은 정적 팩토리 `from(다른 형)`·`of(구성요소)` 다. `of` 32곳, `from` 29곳, `create` 2곳. Lombok `@Builder` 0.
- 응답 DTO 는 도메인에서 `from` 으로만 만든다(`BoardResponse.from(board)`). 반대로 엔티티→도메인은 인스턴스 메서드 `toDomain()` 이다.
- sealed 인터페이스 + 중첩 record 로 선택지를 표현한다. `…/api/vehicle/domain/VehicleSeat.java`(`Exact`·`Unknown` enum 싱글턴), `…/api/vehicle/dto/SeatResponse.java`(`@JsonProperty("kind")`), `…/collector/RemainingSeats.java`, `…/processor/ArrivalLabel.java`.
- JPA 엔티티는 class 다. api 는 읽기 전용 접근자 또는 `toDomain()`, worker `ObservationBatchJpaEntity` 는 `markDispatching`·`conclude`·`reopen` 같은 상태 전이를 가진다.
- migration-tool 은 record 를 파일 안 중첩형으로 많이 둔다(db 패키지 중첩형 90개).
- 널이 될 수 있는 구성요소는 record 주석에 적고 형으로는 표시하지 않는다. `SeatForecastInput.sameDayFullOutcomes` 가 그렇다. `@Nullable` 은 0곳.

## 7. 트랜잭션 경계

코드 안에 세 방식이 이유와 함께 적혀 있다(학습 노트 13장 §1-3 #21).

| 방식 | 어디 | 이유(코드 주석 요지) |
| --- | --- | --- |
| `@Transactional(REQUIRES_NEW)` | `…/collector/ObservationBatchLedger.java` `reserve`, `markDispatching` | 자리와 batch 를 먼저 커밋해야 죽은 프로세스가 남길 수 없는 기록이 남는다 |
| `TransactionTemplate` | `…/collector/RouteCatalogLoader.java` `open` | 자기 호출이라 애노테이션이 안 먹었고(리뷰에서 잡힘), HTTP 호출을 트랜잭션 밖에 두려면 경계가 메서드가 아니라 블록이다 |
| 빈 분리 | `…/processor/ForecastBatchWriter.java` | 한 batch = 한 트랜잭션. 같은 빈 안 자기 호출은 프록시를 안 거친다 |
| `readOnly + REPEATABLE_READ` | `…/api/*/application/*QueryService.java` | 두 문장이 같은 스냅샷을 봐야 한다 |

`@Transactional` 은 worker 14, api 3 곳이고 `readOnly` 는 api 3곳 전부다. `StopDemandStatisticsJob` 은 경계를 포트 구현(`JdbcStopDemandStatisticsRepository.append`)에 두고 javadoc 으로 이유를 적었다.

## 8. 로깅

- `private static final Logger log = LoggerFactory.getLogger(X.class);` 11 파일, `@Slf4j` 1 파일.
- 메시지는 한국어 문장 + `키={}` 꼴이다. `log.warn("하루 호출 한도가 남지 않아 수집을 건너뛴다. 이 판은 관측이 비어 있다. 노선={} 묶음={}", …)`.
- 레벨 규칙이 `ApiExceptionHandler` javadoc 에 있다. 서버 잘못 WARN, 요청 잘못 INFO.
- `System.out/err` 는 migration-tool CLI 출력 3곳뿐이다.
- `GbisApiCaller` 에 `// TODO 로깅 혹은 저장 시 serviceKey 를 마스킹해야 한다` 가 main 유일의 TODO 다.

배정 메모의 "팀은 주석을 적게 쓴다"는 api-app·migration-tool 에는 맞고 worker-app 에는 맞지 않는다. worker-app 은 클래스·상수·SQL 상수·포트 메서드에 javadoc 이 붙어 있고, 문장은 "무엇을 하는지"가 아니라 "왜 이렇게 했고 안 하면 무슨 일이 나는지"다.

### 10-2. 문체

- 클래스 javadoc 첫 줄이 역할 한 문장, 이어서 `<p>` 단락으로 결정 이유와 실패 모드. 강조는 `<b>`. `{@link}`·`{@code}` 사용. 예: `…/processor/ForecastRuntime.java` "예보 배치가 도는 배포와 모델을 따로 읽지 않게 하는 자리다. 따로 읽으면 승격이 일어나는 순간에 …".
- 상수 javadoc 에 산출 근거를 적는다. `ForecastJob.LEFT_BEHIND_LOOKBACK`, `ForecastProperties.MAX_STALENESS`.
- SQL 상수 javadoc 에 인덱스 조건과 글자가 같아야 하는 이유, V 번호를 적는다(`JdbcSeatForecastRepository.SELECT_FORECASTS_AWAITING_LABEL`).
- 테스트 클래스·상수에도 같은 꼴로 붙는다(`MigrationOrderTest`, `JdbcSeatForecastRepositoryTest` 의 `RESPONSE_RECEIVED_AT`).
- 리뷰에서 잡힌 사건을 코드에 남긴다. `RouteCatalogLoader.open` "실제로 그렇게 두고 있었고 동키가 리뷰에서 잡아줬다".
- yml 도 같다. worker `application.yml` 주석 23줄(한도 산수, 5분의 짝, 콜론 뒤를 비우는 이유), api 3줄.
- 언어는 한국어다. migration-tool 의 javadoc 12블록도 한국어이고, 영어는 예외 코드·`RUNBOOK.md`·`FIELD-MAPPING.md` 같은 migration-tool 문서다.

## 11. 커밋·PR

- 제목 `type(SAL-n): 한국어 한 줄 (#PR)`. type 은 feat·fix·setup·chore. squash merge 라 히스토리가 PR 단위다.
- PR 템플릿은 작업 내용 / 확인 사항 체크 2개 / 참고 사항.
- 운영 문서는 `backend/deploy/RUNBOOK.md`(한국어), migration-tool 문서 6개(영어). 코드 옆 `docs/` 디렉터리는 없었고 이 문서가 처음이다.

## 12. 기존 팀 합의

코드 밖에 컨벤션 문서는 없다. 있는 것은 셋이다.

1. 컨플루언스 「0817 BE 객체 구조」의 경계 규칙: 패키지끼리 못 부름, processor 는 학습하지 않음, api 의 두 조회가 표를 공유하지 않음. 앞 둘은 ArchUnit·모듈로, 셋째는 엔티티 분리로 지켜지고 있다.
2. 컨플루언스 「0817 BE DB 스키마」의 DDL 표기 규약: 소문자 타입, `bigserial PRIMARY KEY`, 제약 접두 `ck_ ux_ fk_`, 인덱스 `ix_`. V1~V14 가 따른다.
3. 코드 안 규칙 2개(ArchUnit)와 코드 주석에 적힌 결정들.

`study-deploy-infra/study-input/confluence/` 의 발췌 14편은 FE 배포 기록이고 BE 컨벤션 언급은 없다(PR 리뷰의 "배럴 파일 컨벤션" 칭찬 1건은 FE).
