# 2026-09-23 — SAL-134 변경 이력

- 기록 기준: 2026-09-23, Asia/Seoul. 비교 기준은 PR #70이 반영된 `9f9c75db16fcdefc0944f0c6a40fa7c09e4e1d94`다.
- 요약: 완료된 S3→RDS 이관 기능을 제거하고 노선 관리·관측 수집·탑승 예보의 업무 모델과 저장 책임을 분리했다.
- 상태: 코드 구현과 단위별 로컬 커밋을 진행했다. 최종 검증 결과와 커밋 목록은 [구현 기록](../../docs/refactoring/ddd/implementation-progress.md)에 남긴다. 운영 DB 적용·원격 push·PR 게시·문서 사이트 갱신은 수행하지 않았다.

## 실행 앱과 업무 모듈 분리

- 대상: `backend/settings.gradle`, `business/*`, `integrations/gbis-client`, `api-app`, `worker-app`, `maintenance-app`, `common`.
- 변경 전 → 후: Worker 안의 수집·계산·저장 코드를 업무 모듈로 옮겼다. Gradle 프로젝트는 9개이며 `business`와 `integrations`는 디렉터리다. Worker에는 기동·설정·스케줄을 두고 다른 모듈의 공개 API로 업무를 실행한다.
- 이유: 같은 품질 조사 규칙을 자동 작업과 수동 명령이 공유해야 한다. 정비 명령 때문에 Worker의 모델 적재나 스케줄이 기동되지 않도록 실행 구성을 분리했다.
- 결과: 도메인 규칙은 Spring·JPA·JDBC에 의존하지 않는다. 저장 어댑터는 도메인 객체와 별도 매핑을 사용한다. API 실행 클래스패스의 프로젝트 의존은 API와 common뿐이다. 정비 앱은 필요한 JDBC·트랜잭션·품질 기능만 등록한다.

## 완료된 이관 기능 제거

- 대상: 기존 `migration-tool`의 Java 49개와 전용 자원·스크립트·테스트·AWS SDK 의존.
- 변경 전 → 후: S3 목록·archive·반입·대조·롤백·historical seed·임시 모델 전환에만 쓰던 Java 38개를 제거했다. 품질 조사 업무는 forecasting에 두고 나머지 명령 실행 지원은 maintenance-app에서 재구성했다.
- 이유: 해당 S3→RDS 이관은 완료됐으며 온라인 계산과 품질 정비만 계속 필요하다.
- 결과: 공개 정비 명령은 `quality-preview`, `quality-rebuild`, `quality-status`다. DB에 남아 있는 반입 출처·감사·seed·제외 기록과 Flyway 적용 이력은 삭제하지 않는다. 기존 서비스 V1~V16 SQL도 변경하지 않았다.

## 노선 버전과 호출 횟수 예약

- 대상: `Route`, `RouteVersion`, `JpaRouteRepository`, `DailyCallQuota`, `ApiCallQuota`.
- 변경 전 → 후: 노선 행을 잠근 뒤 최신 버전을 다시 읽고 도메인 규칙에 따라 시간표 변경 또는 버전 교체를 수행한다. GBIS 통신과 일일 호출 횟수 예약은 별도 모듈이 담당한다.
- 이유: 테스트에서 같은 노선의 첫 등록과 같은 개편을 동시에 실행하고, 새 정류장 저장이 실패하는 경우를 재현했다. 서로 다른 버전을 중복 생성하거나 이전 버전만 종료된 상태를 남기면 안 된다.
- 결과: 이전 버전 종료와 새 버전·정류장 저장을 함께 커밋한다. 종료된 버전은 같은 digest라는 이유로 현재 버전으로 반환하거나 수정하지 않는다. 호출 횟수 예약은 호출자 트랜잭션에 참여하며 서울 날짜 변경 시 재예약하는 기존 동작을 유지한다.

## 수집 시도와 입력 확정

- 대상: `CollectionBatch`, `CollectionPlan`, `CollectionAttemptToken`, `CollectionInputs`, `JpaObservationRepository`.
- 변경 전 → 후: 배치 ID와 시도 번호를 함께 전달하고 예약·전송·완료 단계의 상태를 도메인 객체가 검증한다. 예보·평가·품질 조사에서 사용한 원 관측은 `confirmInput`으로 확정한다.
- 이유: 이전 HTTP 응답이 늦게 도착해 새 수집 결과를 덮거나, 계산 근거로 사용한 관측이 재수집으로 바뀌는 경쟁을 막아야 한다.
- 결과: 오래된 시도와 입력 확정 이후 재수집은 거절한다. 같은 시도의 같은 결과를 다시 받아도 관측을 교체하거나 품질 조사를 중복 등록하지 않는다. 호출 예약·전송 기록의 독립 커밋과 관측·품질 요청의 동시 롤백을 유지한다.

## 예보 발행과 평가의 저장 책임

- 대상: `ForecastPublication`, `ForecastEvaluation`, `EvaluationResult`, `DemandStatisticsVersion`과 JDBC 저장소.
- 변경 전 → 후: 발행 정보·예측값·평가 상태·통계 버전 정보를 각각 저장한다. 입력 확정과 발행·예측·평가 대기행 생성은 같은 트랜잭션이다. 평가는 `PENDING`일 때만 확정한다.
- 이유: 같은 배치를 다시 계산해 과거 예측을 덮거나, 평가 재실행으로 당일 누계를 두 번 더하면 안 된다. 테스트에서는 발행 도중 예외, 경쟁 발행, 통계 생성 경쟁, 보정 반영 실패를 재현했다.
- 결과: 배치당 발행은 하나다. 예측 0행도 발행으로 기록하고, 좌석 범위 오류는 해당 차량의 예측만 제외한다. 평가 근거의 도착 정류장은 원 관측의 `stop_order`를 보관한다. 통계 버전 정보와 셀은 품질 잠금 아래 함께 저장한다. 입력 전체 복사나 특징 벡터 추가 보관은 하지 않는다.

## 품질 조사와 모델 활성화

- 대상: `RouteDataQuality`, `TripQualityInvestigation`, `OneWayTripAssessment`, `ModelIdentity`, `ActiveModelSlot`, `ActivateModel`.
- 변경 전 → 후: 품질 상태 변경과 조사 진행 규칙을 도메인 객체로 옮기고 SQL과 분리했다. 편도 연결은 `observation_trip_assignment`에 기록한다. 모델 적재와 활성화는 전체 모델 식별 정보·기대 활성 버전·요청 ID를 사용한다.
- 이유: 자동 조사와 수동 정비가 다른 판정을 만들면 안 된다. 같은 digest의 서로 다른 모델을 구분하고, 동일 활성화 요청을 다시 보내도 결과가 달라지지 않아야 한다.
- 결과: 정상 수집의 추가 품질 SQL 0건, 70/71석·10분·반복 출발·32배치·조사 재개 계약을 유지한다. 수동 명령은 잠금 100ms·SQL 500ms 제한과 단일 트랜잭션을 사용한다. 품질 제외는 이후 제공·평가·보정·통계·학습 조회에 반영한다. 모델 파일은 트랜잭션 밖에서 준비하고 활성 슬롯 변경만 직렬화한다.

## DB 전환과 배포 검증

- 대상: `V17__ddd_storage_expansion.sql`, `V18__ddd_storage_cutover.sql`, `deploy/migrations/SAL-134`, `deploy/runtime-source-inputs.sh`.
- 변경 전 → 후: 확장 DDL과 최종 전환 DDL을 분리했다. 별도 ZIP의 실행기가 PK 단위로 자료와 진행 위치를 함께 저장하고, 전체 값·원 관측·품질 및 학습 조회를 대조한 뒤 최종 전환한다.
- 이유: 앱을 정지한 정비 시간에도 작업이 끊길 수 있으므로 마지막 커밋 다음부터 재개할 수 있어야 한다. 앱의 자동 Flyway가 먼저 실행되더라도 미검증 자료의 기존 컬럼을 삭제해서는 안 된다.
- 결과: 검증 이후 자료가 바뀌면 승인을 무효화한다. 과거 0행 발행의 복원 불가능한 모델은 `LEGACY_UNKNOWN`으로 남긴다. 업무 모듈·GBIS 변경은 Worker digest에 포함하고 maintenance만 바뀌면 서버 digest를 유지한다. 정비 종료 후 새 쓰기를 재개하기 전까지는 DB 백업과 구 JAR를 함께 복원한다.

- 검증: Java 21·PostgreSQL 18 Testcontainers의 규칙·저장·동시성 테스트, 실제 API·Worker·정비 JAR 실행, DB 전환 ZIP 실행, Docker 배포 hook 리허설. 최종 명령·건수는 [구현 기록](../../docs/refactoring/ddd/implementation-progress.md)에서 확인한다.
