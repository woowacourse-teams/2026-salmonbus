# SAL-167 예보 평가 대기와 완료 이력 분리

- 이슈: https://higgs95.atlassian.net/browse/SAL-167
- 기준 dev: d87a09f6. 운영 DB와 Grafana는 변경하지 않았다.

## 동작

- `forecast_evaluation_pending`: 미완료 예보의 관측 ID, 대상 정류장 순번, 노선 버전만 저장한다.
- `forecast_evaluation_result`: 완료 상태와 실제 도착 관측 근거를 보관한다.
- `forecast_evaluation`: 두 테이블을 합친 읽기 전용 뷰다. 기존 통계와 학습 조회의 열과 의미를 유지한다.
- 대기 목록은 한 번 선택하고 중복 원본 관측을 제거해 상세 조회에 재사용한다.
- 정산과 품질 제외는 대기 DELETE와 결과 INSERT를 같은 SQL/트랜잭션에서 수행한다. 실패하면 대기 삭제도 취소된다.
- 등록 전에 같은 키의 완료 결과를 확인한다. 등록과 정산은 기존 노선 행 잠금으로 직렬화해야 한다. `NOT EXISTS`만으로 동시 재등록을 막을 수는 없다.
- 수집/예보/정산 스케줄, 품질 판정, 페이지 순서, 노선별 조회 한도, 확정 제외 500건 한도는 유지한다.

## 배포 조건

V31은 완료 이력을 복사하지 않고 기존 테이블을 결과 테이블로 바꾼다. PENDING 행만 이동한다. 잠금 대기 5초, 개별 SQL 실행 60초 제한을 두며 실패하면 Flyway 트랜잭션 전체가 취소된다. 테이블 잠금과 대기 이동 비용은 발생한다.

**이번 배포는 사용자가 worker 중지와 복구를 수동으로 확인한다.** PR/CI 확인 후 머지 직전에 worker를 중지하고 완전 종료를 확인한다. 복구 가능한 백업과 PENDING 규모, 다른 쓰기 정비 작업의 중지 여부도 확인한다. 이후 기존 API → worker 배포 순서로 API 시작 시 Flyway를 실행하고 새 worker를 시작한다. 중지부터 새 worker 정상 시작까지 수집과 예보 갱신이 멈춘다. 배포 스크립트와 자동 롤백은 변경하지 않는다. 운영 중지/이관/배포는 아직 실행하지 않았다.

- 이관 실패 전: 트랜잭션 취소 후 기존 스키마가 남았는지 확인한다.
- 이관 성공 후: 기존 자동 롤백이 구 버전 worker의 시작을 시도할 수 있으므로 실패 시 사용자가 worker 중지를 확인해야 한다. 구 버전 JAR만 되돌리면 안 된다. 새 구조를 유지한 수정 배포 또는 writer를 멈춘 뒤 검증된 데이터 복구가 필요하다. 운영용 역이관은 이번에 검증하지 않았다.
- `forecast_evaluation`은 물리 테이블이 아니므로 Grafana의 테이블 통계 필터는 `forecast_evaluation_pending`, `forecast_evaluation_result`로 나눠야 한다. 기존 SQL 진단 태그의 변경된 소스 위치는 레지스트리에 반영했다.
- 실제 이관 소요 시간, EBS 크레딧 개선, 장기 vacuum 비용은 운영 미검증이다. 로컬 합성 실험의 감소율을 운영 보장값으로 사용하지 않는다.

## 로컬 검증

- 로컬 테스트 1,053개 통과: 공통 모듈 전체 54개, 예보 모듈 전체 889개, Board 관련 87개, 품질 정비 23개. DB 검증은 PostgreSQL 18에서 수행했다.
- 기존 데이터 이관 후 결과 파일 식별자 유지, PENDING 이동, 완료 근거 보존, 학습 뷰 결과 보존을 확인했다.
- 정산과 재등록의 실제 잠금 경쟁, 중복 정산, 집계 실패 시 롤백, 커밋 후 관측 이벤트, 품질 제외 경로를 확인했다.
- Gradle worker와 JVM 인식 CPU는 1, JVM 최대 힙 512MiB로 한 번에 하나의 검증 명령을 실행했다.
