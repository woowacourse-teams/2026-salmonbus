# 과거 시점 기준으로 재학습한 레스+동키 모델

2026-11-04, SAL-359. 사용자가 전체 좌석 MAE 최소화와 미래 정보 제외를 요청했다. 운영 원본에서 레스의 하차 posterior·좌석 회귀와 동키의 3단계 분류·시간 경계 검증을 결합한 별도 연구 판본을 만들었다. 강화학습은 사용하지 않았다.

## 무엇을 바꿨는가

- 원본 DB 추출 CSV 중 LIVE 배치만 사용했다. `input_confirmed_at >= response_received_at`을 확인하고 확인 지연 90초 초과, 누락, 모호한 중복을 제외했다. 사용한 81개 원본 파일의 SHA-256이 수집 manifest와 모두 일치했다.
- 같은 차량·노선 판본·방향의 연속 관측으로 방문을 연결했다. 90초 초과 공백이나 역행은 연결을 끊는다. 다음 실제 정류장의 관측으로 종료가 확인된 뒤에만 이전 방문을 과거 이력에 넣었다.
- 입력의 정원 대용값은 해당 차량에서 그 시점까지 본 최대 좌석이다. 전체 기간 최대값을 과거 입력에 사용하지 않았다.
- 과거 통계, 이동시간 중앙값, 목표 정류장 평균과 하차 계수는 10월 12일 전에 확정된 자료로 고정했다. 예측 입력의 당일 집계는 예측 시각까지 확정된 이력만 조회한다.
- 하차 posterior 식은 레스를 유지했다. 첫 연구 판본의 계수는 노선/출퇴근 시간대별 공유 계수로 추정했다. 고정 최대 600행, 두 초기값, 제한된 L-BFGS-B 최적화로 계산량을 제한했으며 16개 그룹이 모두 수렴했다. 기존 정류장별 계수를 그대로 사용한 모델은 아니다.

하차 후 좌석은 도착 전후 좌석과 승하차 모형으로 만든 추정 정답이다. 실제 하차 인원이나 실제 물리 정원을 측정한 정답으로 설명하지 않는다. 계수 판본과 평가 표본이 달라 과거 보고의 MAE 2.2289석과 직접 비교할 수 없다.

## 검증

- 8개 노선에서 10월 17일 이후 관측을 삭제하고 학습 구간의 입력을 다시 만들었다. 809,425개 예보 × 88열 = 71,229,400개 값이 모두 동일했다.
- 입력 확인 시각 누락/역전, 종료 witness, 미래 최대 좌석, 관측 공백, 확정 시각 경계와 라벨 purge를 합성 검사로 확인했다. 관련 Python 검사 총 28개 통과.
- 표본 65,536개에서 고정 통계와 표본 계산을 대조했다. 전체 입력의 목표 통계 5,056,632개 float32 값이 내보낸 번들과 일치했다.
- 선택 모델 저장/재로딩 후 마지막 기간의 모든 좌석 예측이 정확히 같았다.
- 실제 새 입력 1,024개와 합성 경계 481개에서 Java/Python 대조 통과. 좌석 차이 0, 확률 최대 차이 1.11e-16. 허용 오차는 기존 1e-9를 유지했다.
- 사용자 요청에 따라 전체 GitHub CI 재실행은 하지 않았다. Java 제품 코드는 이번 학습 단계에서 변경하지 않았다.

삭제 경계와 실제 자료에서 확인한 결과이지, 모든 가능한 누수나 실제 DB commit 순서를 증명한 것은 아니다. 재생 시각은 기록된 `input_confirmed_at` 기준이고 DB commit/화면 소비 시각은 미확인이다.
