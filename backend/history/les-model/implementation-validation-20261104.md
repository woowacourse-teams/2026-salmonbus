# 레스·동키 결합 기준 모델 구현과 검증

이번 구현은 레스의 좌석 회귀기와 동키의 3단계 좌석 분류 구조를 결합한 `gate_base`를 서비스에 연결하는 기반이다. 하차 후 좌석 점예측과 출발 만석 확률을 따로 발행·정산한다. 사용자 요청으로 최종 목표는 두 연구의 장점을 결합하는 것으로 확장됐다. 현재 결합을 비교 기준으로 보존하며, 추가 후보의 채택이나 운영 활성화는 완료하지 않았다.

## 구현 범위

- 고정 통계·트리·입력 계약을 하나의 불변 번들로 로드하고, 지원 노선·정류장 판본·평일 출퇴근·1~12정류장 범위를 확인한다.
- 원관측에서 좌석 88열과 확률 80열을 만든다. 필요한 이력이 누락되면 발행을 완료 처리하지 않고 복구 후 재시도한다.
- 누적 이력은 체크포인트와 필요한 최근 관측으로 보존한다. 원자적 교체, 해시 검증, 재시작, 이전 미발행 배치 재처리를 지원한다. 읽기 전용 `les-history-bootstrap`으로 준비할 수 있다.
- 새 예보는 두 목표와 입력 snapshot·모델 해시를 저장한다. 기존 정수형 좌석 정산·수요 표본·당일 확률 보정에 새 추정 좌석을 섞지 않는다.
- 정산·품질 재평가·보관·원본 삭제·복원은 목표와 판본을 보존한다. 파일 전송은 application 서비스가, DB 트랜잭션은 저장 어댑터가 처리한다. `les-evaluation-restore`로 검증된 파일에서 특정 결과를 복원한다.
- API와 화면은 하차 후 좌석과 출발 시 좌석 여유를 구분한다. 개인의 탑승 성공 확률로 표현하지 않는다.

## 이전에 실행한 전체 검사와 현재 범위

사용자가 GitHub CI에서 확인할 문제는 지금 검사하지 않아도 된다고 요청했다. 이후 전체 CI 재실행·배포 이미지 빌드·JAR 패키징은 하지 않고 위 관련 검사와 계산 대조만 실행했다.

이 요청 전에 프론트 lint·format·typecheck·단위 테스트·production/local 빌드가 통과했고, Playwright MCP로 Chromium·Firefox·WebKit·iPhone 15 전체 1,041개가 통과했다. 기존 건너뛰기 19개는 유지했다. 화면 제품 코드와 E2E 기대 문자열은 그 이후 바뀌지 않았다.

초기 서버 `clean build --continue`는 새 테이블의 로컬 초기화 누락, 이전 브랜치를 가리키는 마이그레이션 검사, 저장소 예외 변환 기대값, 보관 어댑터의 계층 의존, 늘어난 테스트 개수 기준에서 실패했다. 실코드/검사를 수정하고 관련 검사를 재실행했다. 최종 전체 CI 성공으로 보고하지 않는다. 테스트 기준 수는 초기 전체 실행의 API 876·forecasting 1411·maintenance 39에 이후 복원 명령 검사 5개를 반영했다. 최종 전체 개수 검사는 CI에서 다시 확인한다.

## 가독성 검토

Confluence 「BE Java 코드 컨벤션 초안」 판본 6을 전체 읽고 적용했다. 프로젝트 `AGENTS.md`에 최신 본문 필독을 명시했다. var·else·삼항·wildcard·불필요한 전체 타입 경로를 제거하고, 명시 타입·불변 원시 타입 final·한글 테스트명·프로젝트 중첩 타입의 소유자 표기를 적용했다.

입력 계산은 관측 원점, 선행 차량, 같은 배치 차량, 대기 상태, 경로, 당일 수요, 배열 조립으로 나눴다. 경유 특징과 체크포인트 JSON 검증을 별도 객체로 분리했다. 번들 로드는 파일·입력 계약·통계·트리·시각·검증 근거를 나눴다. 트리의 분기 판정과 합산 순서를 이름으로 드러냈다.

5개 이상 필드인 객체는 같은 입력·출력·저장 계약인지 검토했다. 계약 DTO와 순서가 중요한 집계 상태는 개수만 줄이려고 분리하지 않았다. 순차 상태 갱신, 고정 입력 배열, SQL 매핑처럼 함께 읽어야 하는 메서드는 검토 후 유지했다. 긴 SQL·JSON 데이터는 줄 길이 예외이며 포맷 전후 문자열 값을 대조했다.

## 운영 전 남은 것

현재 코드가 원본 파일을 읽어 계산하는 것과 운영에서 예보가 좋은 것은 다르다. 새 기간 성능, 온라인 시점 기준 입력 대조, 실제 규모 Worker 재생, 조회량·메모리·tick 지연, 원격 저장소 권한·전송은 아직 미검증이다. 운영 검증 자료를 만들기 위해 PASS를 임의로 채우지 않는다. 검증 보고서 자동 생성 경로도 아직 제공하지 않는다. 세부 제약은 `serving-verification.md`, `settlement-contract.md`를 따른다.

새 동키 ZIP의 핵심 문서와 선택 모델 4개 파일은 기존 레스 인계 안의 동키 자료와 바이트 해시가 같다. 동키의 LOW16·Q35 학습을 그대로 도입할지, 약하게 조정할지는 평균 오차·낙관 실수·과소예측을 같은 정답과 표본에서 비교한 뒤 정해야 한다. 두 연구의 서로 다른 정답 값을 직접 평균 내지 않는다.
