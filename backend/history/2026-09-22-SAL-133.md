## 검증과 남은 작업

측정은 운영 데이터가 아닌 합성 자료이며, RDS 안전이나 자원 감소율을 보장하지 않는다.

### dev와 같은 자료로 비교한 조회 비용

- 비교: upstream/dev `6f70826`의 `JdbcVehicleTrajectoryRepository` SQL과 현재 SQL. 같은 30대, 20초 간격, 300/3,000묶음(9,000/90,000관측), 최근 30분 2,700관측. 정상 반환 결과가 같은지 확인했다.
- 환경: PostgreSQL 18.6 로컬 컨테이너 CPU 1/메모리 128MiB, shared_buffers 16MiB, work_mem 1MiB, 병렬 쿼리 0. Java 21, CPU 1, heap 256/384MiB. 높은 부하의 작업은 순차 실행했다.
- 방법: 14회 중 앞 4회 제외, dev/현재 실행 순서를 교대하고 남은 10회 정렬에서 6번째 값을 기록했다. JDBC 조회·매핑·조립을 포함한 로컬 시간이다. 전체 예측 시간이나 순수 DB 시간은 아니다.

| 합성 원본 수 | dev 조회 시간 | 현재 조회 시간 | 조회 SQL 수 |
| --- | ---: | ---: | ---: |
| 9,000 | 5.00ms | 7.03ms | 각각 4회 |
| 90,000 | 4.42ms | 6.20ms | 각각 4회 |

현재 조회에는 약 1.8~2.0ms의 품질 확인 비용이 남는다. “정상 수집 추가 SQL 0”은 이상 발견 단계만 뜻하며 예측/API 전체 추가 비용이 0이라는 뜻이 아니다.

`EXPLAIN (ANALYZE, BUFFERS, WAL)`로 읽기 범위도 확인했다.

| 현재 조회(90,000관측) | 확인한 실제 작업 | 로컬 SQL 실행 시간 |
| --- | --- | ---: |
| 30분 이력 | 원본 2,700행, shared hit 74블록 | 2.845ms |
| 30대 최대 잔여석 | 좌석 인덱스 30개 후보와 품질 PK 30회 확인, shared hit 270블록 | 0.145ms |
| board 적격 조건만 재현 | 대상 묶음 30행과 PK 30회 확인, shared hit 122블록 | 0.052ms |
| 한 차량 역방향 조사 페이지 | 32묶음 반환, 묶음 인덱스 33행과 차량 인덱스 32회, shared hit 99블록 | 0.053ms |

위 수치는 단일 실행 계획이다. board 전체 JPQL/HTTP 응답의 성능 수치가 아니다. 해당 조회들에서 임시 파일 쓰기는 0이었지만, 이를 전체 쿼리 메모리나 RDS 메모리 한도로 해석하지 않는다. 데이터가 커지거나 분포·캐시·동시 실행이 바뀌면 실행 계획과 비용도 바뀔 수 있다.

초기 비교에서 90,000행 전체를 읽는 중복 조회(약 33ms)를 발견해 제거했다. 다른 조인 형태도 최대 잔여석 인덱스를 깨뜨리는 것을 확인해 채택하지 않았다. 최종 코드에는 필요한 묶음 조건과 후보 ID 품질 조회를 명시했다.

| 이상 발견 단계 | SQL 호출 | 논리적 변경 |
| --- | ---: | --- |
| 정상 1대/30대 | 0 | 없음 |
| 최초 이상 1대 | 4 | 조사 1행과 노선 버전 1행 |
| 최초 이상 10대 | 13 | 조사 10행과 노선 버전 1행 |
| 같은 진행 중 차량의 반복 이상 | 2 | 새 조사/버전 UPDATE 없음. 노선 잠금은 남음 |

조사/수동 정리는 원본 좌석이나 예측을 삭제하지 않는다. 조사 페이지의 관측 키 UPDATE는 해당 차량의 최대 32개 관측만 대상으로 하며, 편도/진행 행 쓰기가 추가된다. 반환 수 제한이 인덱스 내부 검사 횟수나 모든 DB 자원을 같은 수치로 제한하지는 않는다.

- 측정 코드/원본 계획: 세션의 `/tmp/sal133-event-perf/Compare.java`, `BaselineJdbcVehicleTrajectoryRepository.java`, `results.tsv`. 임시 파일은 저장소 커밋 대상이 아니므로 지속 보존을 보장하지 않는다.
- 남은 확인: 운영 규모·실제 자료 분포·동시 수집/예측에서의 SQL 비용과 노선 잠금 대기, RDS CPU/메모리/크레딧, 운영 시간 정책, 배포/기존 자료 정리 실행. Gradle/Testcontainers 및 로컬 CLI의 후속 결과는 아래에 기록한다.
